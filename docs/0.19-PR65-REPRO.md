# 0.19 PR #65 filtered-vector reproducer

November 5, 2026. This is a tiny reproduction of an external report, not completion
of the E2 measurement protocol or evidence to select a new traversal algorithm.

The fixture adapts `line_db` and `hnsw_filter_does_not_truncate_the_result` from
[kmaragon's PR #65](https://github.com/shuruheel/mnestic/pull/65), immutable source
`e7fba2abf4b88ce153e880ca2e8b022af391826d`. The script retains MPL-2.0 attribution.
It uses existing backends and query options; layered storage and the proposed
`validity:` option are not imported.

```sh
.venv/bin/python scripts/mnestic_019_filter_repro.py \
  --output results/sample/0.19/pr65-018-baseline.json
```

The installed 0.18.0 package was exercised with three independently built tiny
databases per backend. The corpus contains 25 two-dimensional points `[k,k]`;
the query is `[0,0]`, k=3, and the rare eligible keys are `[20,22,24]`. Exact
squared-L2 distances establish that eligible truth without relying on another ANN
implementation. Empty and fewer-than-k eligible sets are included.

On both SQLite and RocksDB, all three builds returned no rare-type results at
ef=3 and ef=5; ef=50 and the protocol sweep ef=100/200/400/800/1600 returned all
three eligible keys. No ineligible or duplicate keys were observed in the 144
query observations. The empty case returned no rows throughout.

[Raw observations and manifest](../results/sample/0.19/pr65-018-baseline.json)
record the exact queries, installed extension hash, script hash, fixture,
platform, harness state and un-warmed elapsed times. These times are not latency
claims. The HNSW topology seed is uncontrolled; fixed vectors are not a seeded
index build. A subsequently downloaded 0.18.0 wheel contains the identical installed extension;
its filename and SHA256 are appended to the manifest. Baseline/candidate build
equivalence still needs release qualification.

This reproduces the reported low-ef omission and shows that widening recovers
this particular fixture. It does not establish quality or bounded cost at larger
scale. Remaining E2 work includes the selectivity/adversarial matrix, stable
snapshot widening, shared deadlines, memory/work measurement, updates/deletes,
filtered FTS fusion, and a paired immutable candidate. No new engine mechanism is
selected from this result.


## FTS-fix validation wheel

The same committed reproducer (`0ce1843`) was run against a separate local wheel
containing PR #69 on current main. Its 144 query outcomes match the baseline,
including empty/fewer-than-k cases. The candidate wheel's source reference,
features, installed extension hash and wheel SHA256 are recorded with the
[candidate observations](../results/sample/0.19/pr65-fts-candidate.json).

This wheel is an unoptimized development build for correctness validation; it is
not the final 0.19 candidate. Do not compare its timing samples with the released
baseline's optimized wheel or treat these tiny cases as the full E2 gate.
