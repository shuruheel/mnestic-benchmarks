# Bind vectors and values as parameters

Keep query text stable and pass the numerical vector as a value. This avoids
constructing and escaping a long vector literal in client code. It does not
eliminate parsing/planning, and no measured latency or cache recommendation is
claimed here. The E3 paired timing campaign is deferred to a dedicated quiet window.

```python
from mnestic import CozoDbPy

db = CozoDbPy("mem", "", "{}")
db.run_script(":create doc {id: Int => emb: <F32; 2>}", {}, False)
db.run_script("?[id,emb] <- [[$id,$v]] :put doc {id=>emb}",
              {"id": 1, "v": [1.0, 0.0]}, False)
db.run_script("::hnsw create doc:vec {dim:2,fields:[emb],distance:Cosine,"
              "dtype:F32,m:8,ef_construction:50}", {}, False)
script = ("?[id,d] := ~doc:vec{id | query:vec($qv),k:$k,ef:$ef,"
          "bind_distance:d} :order d,id")
rows = db.run_script(script, {"qv": [1.0, 0.0], "k": 10, "ef": 100}, True)["rows"]
assert rows == [[1, 0.0]]
db.close()
```

For 384 or 1536 dimensions, retain the same pattern and make the stored vector
schema/index dimension match the input. The Python binding takes a dictionary,
not a JSON-encoded parameter string. Convert NumPy arrays with `.tolist()` when
needed. Parameter names substitute values; they do not substitute relation names
or other syntax. Validate any intentionally dynamic identifier separately.

Use `candidates:$keys` for candidate-aware FTS. HNSW's inherited `filter:` works
after its global ef-sized candidate search, so a rare eligibility predicate can
still return too few rows. An exact eligible-key join is a useful reference:

```text
eligible[id] <- $key_rows
?[id,d] := eligible[id], *doc{id,emb}, d=cos_dist(emb,vec($qv))
:order d,id :limit $k
```

Here `key_rows` is a list of one-column rows, for example `[[1], [7]]`. Bound the
eligible set in the caller. This is an exact scan of those keys, not an ANN
candidate API or a promise of bounded latency/memory for arbitrary input sizes.

The campaign checks literal/parameter result equality at both dimensions, across
one/three-query requests and repeated/changing vectors. Only the tiny harness
checks have completed. Serialization, construction and engine-call timings are
separate; their difference is not pure parser time. Phase instrumentation and a
real request-frequency profile are still required before the plan-cache gate can
be assessed. A cache remains outside the 0.19 scope.
